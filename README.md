# Chuanmen

**Chuanmen（Chuanmen）——去邻居家坐一会儿：不用预约、不用准备、走的时候不留痕迹。**

落到产品上就是：让物理上同处一室的人，像把设备摊在同一张桌子上一样共享东西。

局域网直连，扫码即连，传完不留痕。没有账号，没有云端，不是网盘。

起点是传文件，方向是**临时的协作空间**：同一张桌子上，你可以放文件，也可以贴一段文字或链接，
对方扫码 / 发现 / 从引导页下载客户端，进来就能取。散会即消失。

> **项目状态**：内部开发阶段。内核与命令行客户端有自动化测试覆盖（104 个用例，
> 含真实的端到端传输与断点续传），桌面端可以构建运行，但**界面尚未经过真机验收**。
> 详见文末「项目状态」。

---

## 它解决什么

会议室里，你想把 2GB 的素材给旁边的同事。现有做法都不顺：

| 做法 | 问题 |
|---|---|
| 微信 / QQ | 压缩画质、限制大小，还得先加好友 |
| 网盘 | 先上传再下载——同一间屋子里绕了一圈公网，数据还留在了云上 |
| U 盘 | 要拔插，还要找到那个 U 盘 |
| AirDrop | 只认苹果设备 |

Chuanmen 的做法：你在自己电脑上开一个房间，屏幕上出现二维码；
对方扫一下就连上，文件走局域网直传。1GB 是几秒钟的事，不是"等着上传"。

## 现在能做什么

### 桌面端

分享者：打开应用 → 把文件或文件夹拖进窗口（或用「选择文件…」）→ 点「开始分享」→
屏幕出现二维码，**同时向局域网广播**（对方点「搜索附近设备」就能看到这台设备）。
（也可以只发一段文字/链接；填了「对方放进来的东西存到哪」就表示
**这次也收东西**——房间是双向的。）

接收者：点「搜索附近设备」→ 列表里出现对方 → 点「接收」。
（也可以扫二维码或粘贴连接串，三条路等价。）想放东西给对方，就在下面写一段话/选几个文件。

界面只有四个状态：**首页 → 等待接收（二维码）→ 传输中（进度）→ 结果**。
另有「诊断网络」按钮：连不上时先跑它，而不是自己猜。

### 命令行

```bash
cargo build --release

# 分享文件（会打印二维码，同时向局域网广播）
./target/release/chuan send ./photos

# 也可以只发一段文字 / 一个链接（对方不用落盘，直接看到）
./target/release/chuan send --text "把这段字送到那台机器上"

# 文件和文字可以一起发；--to 表示"我也收东西"，对方放的会进这个目录
./target/release/chuan send ./报告.pdf --text "链接：https://example.com" --to ./收到

# 接收端也能往房间里放东西（对方会收到）
./target/release/chuan receive --to ./下载 --send ./我的草稿.docx --text "这是我改的那版"

# 接收：不用扫码、不用粘贴，会列出附近正在分享的设备让你挑
./target/release/chuan receive --to ./downloads

# 对方网络封了 UDP？加 --tcp 直接走回退通道（不加也会自动回退，只是先等一次 UDP 超时）
./target/release/chuan receive --to ./downloads --tcp

# 也可以直接带连接串（扫码/粘贴得到的那串）
./target/release/chuan receive "cm1:..." --to ./downloads

# 单独看看附近有谁在分享（发现不到设备时用它排查）
./target/release/chuan discover

# 网络自检：连不上时用它判断问题出在哪
./target/release/chuan diagnose "cm1:..."

# 看看记住过哪些设备（本机记录；忘掉一台用 --forget 加指纹前几位）
./target/release/chuan devices
./target/release/chuan devices --forget 3f9a
```

`chuan send` 支持 `--port`、`--name`、`--no-qr`（只打印连接串，适合远程终端）。
`chuan receive` 不带连接串时先发现附近设备；只有一台就直接连，多台会让你选序号。
`chuan receive --tcp` 强制走 TCP 回退；不加时会先试 QUIC，走不通再自动回退
（会在终端里说一句"UDP 那条路没走通"，不让你对着那 8 秒发懵）。

### 桌面端怎么跑

```bash
cargo run -p chuanmen-desktop
```

> 注意：仓库的 workspace 配置了 `default-members = ["crates/core", "crates/cli"]`，
> 所以日常的 `cargo build` / `cargo test` **不会**构建 Tauri（它的编译产物有 1–3 GB）。
> 只有显式 `-p chuanmen-desktop` 时才会。

**做一个安装包（Windows）**：

```bash
cd crates/desktop
npx @tauri-apps/cli build          # 产出 target/release/bundle/nsis/Chuanmen_<版本>_x64-setup.exe
```

装出来的是**按用户安装**（`%LOCALAPPDATA%\Chuanmen`，不需要管理员权限），
带开始菜单快捷方式，控制面板可卸载。安装包约 2.5 MB（WebView2 用系统的；
Windows 10/11 一般都自带）。

> **没签名**。我们手上没有代码签名证书，所以 Windows SmartScreen 大概率会拦一下
> （"更多信息 → 仍要运行"）。要签名就买一张 OV/EV 证书，然后：
> `signtool sign /sha1 <证书指纹> Chuanmen_0.1.0_x64-setup.exe`，
> 或者把证书指纹写进 `tauri.conf.json` 的 `bundle.windows.certificateThumbprint`
> 让 Tauri 在打包时自动签。签名解决的是"下载的人敢不敢点"，不影响功能。

## 已经验证的能力

| 能力 | 实现方式 |
|---|---|
| 文件与文件夹传输 | 保留目录结构；相对路径经安全校验，绝对路径、`..`、Windows 保留名一律拒绝 |
| 双向共享空间 | 不止"我发你收"：**双方都能往房间里放东西，而且两个方向同时跑**（各占一条 QUIC 流）。主机加 `--to 目录` 表示也接东西，接收端加 `--send 文件`（或 `--text`）就能把自己的东西放进去。实测 400MB 双向交换 1.57 秒（比单向还快，说明真的在同时传） |
| TCP 回退 | QUIC 走 UDP，而企业网络、访客 WiFi、部分 VPN 会直接封掉 UDP。主机在同一个端口（或另给的端口）上同时开一条 **TLS over TCP** 通道，接收端 UDP 走不通就自动换路——帧协议与 QUIC 完全同一套，物品收发的代码一行没改。两个方向各占一条 TCP 连接（一个方向一条，天然并发）；回退端口随连接串和 mDNS 广播一起传过去，老版本客户端不认识那个字段，照旧走 QUIC |
| 文本 / 链接 | 和文件走**同一套传输**（一样分块、一样 BLAKE3 校验），但不落盘：接收端直接显示，桌面端可一键复制。可以文件 + 文本混着发 |
| 完整性校验 | 每个文件传完用 BLAKE3 校验，不匹配就不改名为正式文件 |
| 断点续传 | 中断后只补缺少的部分，**而且会自动重连**（1s/2s/4s 退避，最多 4 次），不需要用户手动重跑。本地进度带**前缀内容哈希**——长度够不代表内容是我们要的，所以每次续传都真的核对前缀 |
| 指纹校验 | 只接受证书指纹与二维码一致的主机，不一致**秒级失败**并明确提示 |
| 大文件 | 流式读写，不把文件读进内存；接收前**真正预分配**空间，磁盘不足在传输开始前就报错 |
| 免安装引导 | 主机分享时会顺手开一个**只读**小页面（`http://<局域网IP>:<端口>`）。对方用浏览器打开就能把客户端下走——**就是主机正在运行的这个 exe**，下载后双击即用（无参数运行 = 发现附近设备并接收）。不需要安装、不需要联网下载 |
| 附近设备发现 | mDNS/DNS-SD：对方在分享就会出现在列表里，**不用扫码**。每台设备显示一个由证书指纹派生的 6 位验证码，两边对一眼即可确认身份 |
| 设备簿（最近的人） | 成功连过的设备记在本机（指纹 + 名字 + 次数 + 上次时间）：搜索列表和连接前会提示"上次连过"，让你不用再对一次验证码。**指纹照旧每次连接都验**——设备簿只是"记住"，不是"免检"。同一个名字换了指纹会明确警告（重装 or 冒充，两种情况都值得看一眼） |
| 主动停止 | 协作式取消（不是杀进程）：已收部分保留，下次能接着传 |
| 网络自检 | 逐个候选地址真发握手探测，给出结论与可操作的排查建议 |
| 不留痕 | 全部成功后会清掉本地临时状态文件；不联网、不上传任何数据 |

实测：600 MB 文件在传输中被强杀后重连，只补传了缺的 452 MB，最终字节一致。
真机验收（单机 Windows，真实二进制）：400 MiB 单文件 1.76 秒 / 237 MB/s（含校验）；
双向房间 8 MiB + 6 MiB + 两段文本 0.20 秒；主机重启（新二维码、新会话）后接着传，
只补 160 MiB。另一台设备用浏览器打开引导页拿到 exe、**双击无参数运行**就能发现并接收，
全程不用扫码。

### 速度，以及为什么曾经慢

先给数字。回环基准（`cargo run --release --example bench -p chuanmen-core -- 512`，
在一台 2 核 / 2.6 GHz 的虚拟机上）：

| 项目 | 速度 |
|---|---|
| 端到端传输（含加密、分帧、落盘、校验） | **185–205 MiB/s** |
| 磁盘裸拷贝（对照组） | 1113 MiB/s |
| BLAKE3 单线程（对照组） | ~1400 MiB/s |

修复前的局域网实测只有 **30–55 MB/s**，而其中大部分是白烧的。两个真实瓶颈：

1. **检查点把整个前缀重算一遍。** 续传检查点每 8 MB 写一次，每次都要重算"已收到的全部
   数据"的 BLAKE3，总开销就是 8+16+…+总大小，也就是 **O(n²)**——512 MB 的文件要哈希
   约 16 GB 数据，600 MB 的文件光这一项就是十几秒。它把吞吐按在 50 MB/s 上，而且在耗时
   归因里完全看不出来（看代码只会觉得"顺手算个哈希"）。现在改成边收边算、检查点只对
   哈希器取快照。
2. **UDP 套接字用的是系统默认缓冲区。** Windows 上只有 64 KB，而 QUIC 默认就允许
   1.25 MB 在途数据。内核缓冲区一满**直接丢包**：即使是在毫无真实损耗的回环上，丢包率
   都有 1.8%、17 次拥塞事件。现在收发缓冲都设成 4 MB，回环丢包归零。

修完之后，剩下的天花板是 **CPU**——传输期间约 1.5 个核跑满（Windows 上用户态 QUIC 每
字节的加解密与拷贝开销约 6–7 ns）。也就是说：在同一条 1 GbE 链路（上限 112 MB/s）或普通
WiFi（30–80 MB/s）上，**瓶颈已经回到链路本身**，不再是这个实现。

> ⚠️ **不要靠调大单流窗口来提速。** quinn 0.11 的接收缓冲最多容纳 1024 个不连续分片，
> 超过就以 `INTERNAL_ERROR("too many gaps in stream buffer")` 直接掐断连接（实测触发点
> 约 2.9 MB 未读数据）。默认的 1.25 MB 流窗口刚好在安全区内；要喂饱万兆链路得靠并行
> 多流，而不是加大单流窗口。回环上这曾让一次 512 MB 的传输在 4 MB 处就断掉。

## 工作原理

### 一次扫码，同时传递三件事

二维码里不只是地址，还有**会话 ID** 与**主机证书指纹**：

```
cm1:eyJ2IjoxLCJzaWQiOiI4ZjNj…   （base64url 编码的 JSON）
```

这让"怎么找到对方"和"怎么信任对方"用同一个动作解决——不需要 CA，不需要账号，
也不需要云端参与。信任锚点通过屏幕这个带外信道传递，**安全性等价于 Signal 的安全码比对**。

### 两条路的信任等级不一样（这点必须说清）

扫码那条路，指纹是**带外**来的（屏幕 → 摄像头），能防中间人。

自动发现那条路，指纹和地址是从**同一个信道**（mDNS）来的：能伪造设备列表的人，
也能顺手把指纹一起换掉。所以发现路径的信任等级是 TOFU（首次使用即信任），
和扫码**不等价**。

为此每台设备都带一个**由指纹派生的 6 位验证码**，和主机屏幕上显示的是同一个数字
（`427 913` 这种）。想确认身份就对一眼，不想对就享受"点一下就传"的便利——
两条路都留着，但不会把便利说成"同样安全"。

设备簿（"上次连过"）不改变上面任何一条：它记住的是**指纹**，连接时该验的照验。
它的作用是省掉"再对一次码"这个重复动作，外加在**名字相同但指纹不同**时报警——
那可能是对方重装了（自签证书换了一份），也可能有人顶着同一个名字在中间，两种都该看一眼。

### 传输

QUIC（`quinn`）自带加密与多路复用；用单条双向流跑完整会话（重连后自动续传）。
协议层与传输解耦，将来换传输不影响上层。

### 分层

```
crates/core     内核：传输、协议、加密、续传、自检。不依赖任何 UI
crates/cli      chuan send / receive / diagnose —— 也是长期的测试资产
crates/desktop  Tauri v2 桌面端：薄桥接层 + 原生 HTML/CSS/JS，不引前端框架
```

**内核与 UI 完全解耦**：内核只发出与界面无关的 `ProgressEvent`，
命令行用它画进度条，桌面端用它画进度条——桌面端**没有复制任何传输逻辑**。

## 运行平台

| 组件 | Windows | Linux | macOS |
|---|---|---|---|
| 内核 + CLI | ✅ | ✅ | ✅ |
| 桌面端 | ✅ WebView2（Win10+ 自带） | ⚠️ 需先装 WebKitGTK | ✅ 系统自带 WebKit |

**Linux 上跑桌面端**需要先装 WebKitGTK（Tauri 在 Linux 上用它，不是 Windows 那套 WebView2）：

```bash
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libayatana-appindicator3-dev
```

### 一处真实的平台差异：磁盘空间预留

- **Windows**：把文件长度改大（`SetEndOfFile`）会让 NTFS **真的分配簇**，等于预分配。
- **Linux**：同样的做法只产生**空洞**（稀疏文件）——`ls -l` 看着有 2 GB，实际一个盘块都没占。
  于是"磁盘满"会拖到传到 90% 才爆出来，正好是这一层要防的那种失败。

所以 Unix 上改用 `posix_fallocate` 真正预留空间。这是整个内核里唯一的平台差异，
代码在 `crates/core/src/fs_util.rs::preallocate`。

### CI 保证，而不是靠这句话保证

`.github/workflows/ci.yml` 在 Linux / Windows / macOS 三平台都跑测试与构建。
端到端用例是真的起 QUIC 端点互传文件、真的做断点续传，所以 CI 通过意味着
"能编译"并且"能传"。

## 开发

```bash
cargo test              # 内核 + CLI（默认成员），106 个用例
cargo test --workspace  # 连桌面端一起构建
cargo run -p chuanmen-desktop # 跑桌面端

# 吞吐基准（回环，去掉网络变量）。这是长期的性能护栏：
# 任何改动让吞吐掉了，这里立刻能看出来。
cargo run --release --example bench -p chuanmen-core -- 512
```

测试里包含真实起两个 QUIC 端点互传文件的端到端用例，以及「中断后重连只补差额」、
「**真的把连接掐掉之后自动重连带续传**」、「**真的注册一个 mDNS 广播再把它搜出来**」、「**真的从引导页把客户端下下来（逐字节比对）**」、「**文本条目必须完整到达且不在磁盘上留文件**」、「**双方都能往房间里放东西**」、
「不可信检查点必须整文件重传」、
「指纹不符必须秒级失败」、「取消后必须还能续传」、「一个文件写不进去不能连累其他文件」
这类回归测试。

写测试时的一个规矩：修 bug 之前先把"能复现它"的用例写出来，并且**确认它在修复前真的
会失败**——否则那条测试只是个摆设。

## 项目状态

**已完成**：内核、命令行、桌面端界面、主动停止、网络自检、文件选择器、视觉系统。

**已真机验收**（2026-09-13，单机 Windows；明细见 `docs/ACCEPTANCE.md`）：
真实二进制 + 真实网卡 + 真实窗口跑通了引导页下载、双击即用、mDNS 发现、
双向房间、断点续传（含主机重启）、并发接收端、错误路径，以及桌面端的
「开始分享 → 对方发现并加入 → 结果卡片显示收到的文本」整条链路。
这一轮抓到并修掉了 7 个测试结构抓不到的问题，其中两个在真机上会让核心能力直接不可用
（桌面端分享不广播 mDNS；桌面端缺少 Tauri 事件权限，界面收不到任何进度）。

**仍需人工/第二台机器**：拖放、系统文件/文件夹对话框、终端 Ctrl+C 按键本身、
两台真机之间的 mDNS 与防火墙弹窗、手机端、小时级稳定性。

**已知限制**（现在还没有的，不要期待）：

- **一台主机同一时刻只服务一个接收端**。并发来的第二个连接会排队等第一个传完
  （实测两个 400 MiB 接收端共 5.21 秒，等于串行 2.4s + 2.7s）。房间要真正支持
  "多人同时取"，需要把 accept 循环改成并发任务。
- **自动发现依赖 mDNS**。访客网络开了 AP 隔离、企业网络禁组播、防火墙拦掉 UDP 5353、
  或者本机有别的程序占着 5353 时，都搜不到设备（`chuan discover` 可以判断属于哪种情况）。
  这些情况下**扫码和粘贴连接串照样可用**——发现只是便利，不是必要条件。
- **连不上时要等半分钟才给结论**。重连预算是 30 秒（覆盖"主机刚结束上一个会话"的
  12 秒空闲超时窗口）；如果主机是在传输中被强杀，接收端还要先花 12 秒发现对端消失，
  最坏约 47 秒才报错。期间会持续打印重试提示，不是卡死。
  如果是因为对方封了 UDP，第一发还要多等一次 QUIC 握手超时（8 秒）才会切到 TCP——
  已知这种情况就加 `--tcp`，直接省掉这 8 秒。
- **TCP 回退下主机按"方向"报数**。一个方向一条 TCP 连接，主机的收尾摘要因此是
  两条（"发出去多少"和"收回来多少"各一条），不像 QUIC 那样合并成一条。
  接收端看到的总数不受影响。
- **`--once` 与 TCP 回退**：`--once` 是"服务一个连接就收工"，而 TCP 回退下两个方向
  是两条连接，所以对方要是也想往房间里放东西，第二个方向可能没人接（会明确报错，
  不会静默丢数据）。需要双向时别加 `--once`。
- **设备簿是单向的**：只有接收端记得住主机。主机拿不到访客的证书（没做 mTLS），
  只知道对方报的名字——那个名字不构成身份，所以主机侧不会记"熟人"。
- **设备簿是本机的一个文件**（`%APPDATA%\chuanmen\known_devices.json`）。
  这是"不留痕"里的一个自觉例外：传完的东西一点不剩，但"连过谁"会留着，
  方便下次不用再对码；不想要就 `chuan devices --forget <指纹前几位>`。
- **没有公网能力**。仅限同一局域网；跨网段、AP 隔离、企业防火墙会连不上——
  这种情况下用 `chuan diagnose` 或界面上的「诊断网络」定位。
- **没有移动端**。
- **没有安装包与签名**。客户端可以自己分发（引导页把当前 exe 给对方），但下下来的是
  未签名的 exe，Windows SmartScreen / 杀毒软件可能提示；桌面端的引导页也还没接上。
- **主机停止分享后无法自己恢复**。接收端会自动重连（最多 4 次），但如果主机那边
  已经关掉分享或换了会话，二维码就作废了——这种情况必须重新扫码，任何自动重试都
  救不回来（会话 ID 与证书指纹都对不上了）。
- 仅支持同版本客户端互连（协议版本不匹配会明确报错）。
